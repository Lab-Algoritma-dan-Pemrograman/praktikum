# Update log

Catatan kronologis perubahan penting: apa yang berubah, bagaimana diverifikasi,
dan apa tindak lanjutnya. Tujuannya supaya status terbaru mudah dicari tanpa
membaca ulang seluruh laporan fase.

## Konvensi nama

- `YYYY-MM-DD.md` — ringkasan satu hari (beberapa perubahan sekaligus).
- `YYYY-MM-DD-<topik>.md` — entri mendetail untuk satu topik besar.

Gunakan huruf kecil dan tanda hubung. Jangan menaruh kredensial, token, atau isi
`.env` di entri mana pun.

## Struktur entri

Mulai dari [template](_template.md). Minimal memuat:

1. **Ruang lingkup** — apa yang berubah dan di environment mana.
2. **Perubahan** — daftar ringkas, tautkan file/dokumen terkait.
3. **Verifikasi** — perintah/check yang dijalankan dan hasilnya.
4. **Risiko / tindak lanjut** — yang belum selesai atau butuh keputusan owner.
